Skenario 1–3 — Role Granular (Ardan)

1

Staf approval coba proses refund → ditolak 403

Ardan
❌ GAGAL

Diharapkan: Ditolak (403) karena staf_approval tidak punya permission refund.proses.

Hasil aktual: Ditolak 403, tetapi penyebabnya salah — bukan karena pengecekan permission di controller, melainkan karena middleware AdminOnly sudah memblokir di level route.

app/Http/Middleware/AdminOnly.php:16 16 | if (! auth()->check() || auth()->user()->role !== 'admin') { 17 | abort(403, 'Anda tidak memiliki akses ke halaman ini.'); routes/web.php:99 99 | Route::middleware(['auth', 'admin']) routes/web.php:182 182| Route::middleware(['auth', 'admin'])->prefix('admin')...
⚠️
False positive! Skenario "kelihatan lolos" karena memang 403, tapi penyebabnya middleware level route, BUKAN $this->authorize('refund.proses') di controller. Ini adalah bug yang disebutkan di peringatan soal.
2

Staf keuangan proses refund → berhasil

Ardan
❌ GAGAL

Diharapkan: Berhasil, karena staf_keuangan punya permission refund.proses.

Hasil aktual: Akan GAGAL (403) — middleware AdminOnly mengecek role === 'admin' di level route. staf_keuangan punya role = 'staf_keuangan' → tidak lolos middleware → tidak pernah sampai ke controller.

AdminOnly.php:16 16 | auth()->user()->role !== 'admin' → staf_keuangan ditolak di sini, sebelum controller AdminBookingController.php:60 (method refund) 60 | if (auth()->user()->role !== 'admin') { 61 | abort(403, 'Hanya admin yang dapat mengajukan refund.'); → Method refund() JUGA masih pakai cek lama, bukan $this->authorize() AdminBookingController.php:77 (method refundIndex) 77 | $this->authorize('refund.proses'); → refundIndex() sudah benar pakai Spatie, tapi refund() belum
🚨
Dua lapis masalah:
1. Middleware AdminOnly belum diubah — memblokir semua non-admin di level route.
2. Method refund() (baris 60) masih pakai role !== 'admin', bukan $this->authorize('refund.proses').
Hanya refundIndex() (baris 77) yang sudah diperbarui ke Spatie permission.
3

Super admin akses semua fitur via Gate::before()

Ardan
❌ GAGAL

Diharapkan: Semua berhasil lewat Gate::before() yang mengembalikan true untuk role admin.

Hasil aktual: Gate::before() di AppServiceProvider SUDAH benar, tapi $user->hasRole('admin') akan CRASH karena User model tidak meng-use trait HasRoles.

app/Providers/AppServiceProvider.php:32-34 32 | Gate::before(function ($user, $ability) { 33 | return $user->hasRole('admin') ? true : null; 34 | }); app/Models/User.php:13 13 | use Spatie\Permission\Traits\HasRoles; ← imported app/Models/User.php:21 21 | use HasApiTokens, HasFactory, Notifiable; ← HasRoles TIDAK ADA!
🚨
Trait tidak di-use! Baris 13 meng-import HasRoles dengan use Spatie\Permission\Traits\HasRoles;, tapi baris 21 hanya use HasApiTokens, HasFactory, Notifiable; — trait HasRoles tidak ditambahkan ke statement use di dalam class body. Akibatnya $user->hasRole(), $user->assignRole(), $user->can() via Spatie semuanya akan error method not found.
